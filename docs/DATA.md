# Datasets

Source and licence of every dataset used by vstent. **No patient data is ever committed to this
repository.** All data lives under the git-ignored `data/` folder.

| Dataset | Source | Licence | Location | Used for | Status |
|---|---|---|---|---|---|
| Synthetic vessels v1 | generated by `vstent synth` (`configs/synth_v1.yaml`) | n/a (generated, no patient data) | `data/synth/v1/` | surrogate training / evaluation | generated (M2); see `reports/dataset_card.md` |
| Synthetic vessel trees v1 | generated by `vstent synth-tree` (`configs/synth_tree_v1.yaml`) | n/a (generated, no patient data) | `data/synth/tree_v1/` | tree physics checks (P2), tree surrogate (P3) | generated (P2); see `reports/tree_dataset_card.md` |
| Validation stand-in study | generated by `vstent validate-synthetic` (`configs/validation_synthetic.yaml`) | n/a (generated, no patient data) | `data/validation_synthetic/` | dry run of the validation tool (P4) | generated (P4); see `reports/validation_synthetic.md` |
| ARCADE | Zenodo record 10390295 (DOI 10.5281/zenodo.10390295), `arcade.zip` | CC0 1.0 (Zenodo licence `cc-zero`) | `data/raw/arcade/` | vessel segmentation (`syntax` task), stenosis overlays (`stenosis` task) | downloaded and verified (M5) |

## Synthetic vessels v1

Regenerate with `uv run vstent synth --config configs/synth_v1.yaml` (add `--overwrite` to
replace an existing copy). Splits: train 100k (seed 1001), val 10k (1002), test 10k (1003),
cal 10k (1005; conformal calibration only, added in P1), ood 5k (1004; 80–120 mm, 3–4 lesions). The data folder holds the shards, `manifest.json`
(array units, per-shard content hashes), the resolved `config.yaml` and `run_meta.yaml`
(git commit). Statistics: `reports/dataset_card.md`.

## Synthetic vessel trees v1

Regenerate with `uv run vstent synth-tree --config configs/synth_tree_v1.yaml` (add
`--overwrite` to replace an existing copy). A main vessel with 1–4 side branches, labelled by
the tree solver; the main vessel's single-path FFR is stored for comparison. Splits: train 40k
(seed 2001), val 4k (2002), test 4k (2003), cal 4k (2005), ood 2k (2004; 100–140 mm main
vessel, 4 side branches, 2–3 main lesions). Same folder layout as v1. Statistics:
`reports/tree_dataset_card.md`.

## Validation stand-in study

Regenerated by `uv run vstent validate-synthetic` (seed 4001). Synthetic patients with one to
three vessels; each vessel a synthetic tree (P2 sampler with the overrides in the config)
rendered as a 512 × 512 X-ray-like projection, with its true lumen mask, a `cases.csv`, a
`reference.csv` (the tree solver's FFR on the true geometry) and a `truth.csv` (true geometry
summary). The rendering's contrast, edge enhancement and noise were fitted to centreline
statistics measured on ARCADE `syntax/val` images (DECISIONS D39); no ARCADE pixels are copied.
**Not clinical data.** Real validation data is never stored in this repository
(`docs/validation/DATA_SPEC.md`).

## ARCADE

**Source.** Popov M. et al., *ARCADE: Automatic Region-based Coronary Artery Disease
diagnostics using x-ray angiography imagEs Dataset*, Zenodo record 10390295, version "COCO",
published 2023-12-15, DOI 10.5281/zenodo.10390295. Open access.

**Licence.** CC0 1.0 (public-domain dedication; Zenodo licence id `cc-zero`, read from the
record's API metadata on 2026-10-28). No licence acceptance step was needed.

**Download.** `uv run vstent data arcade` streams
`https://zenodo.org/api/records/10390295/files/arcade.zip/content` (451,573,813 bytes) to
`data/raw/arcade/arcade.zip`, verifies MD5 `c5b1973ade06f7dff210f878161e1a76` (value from the
Zenodo record) and extracts it with path checks. `data/raw/arcade/SOURCE.json` records URL,
checksum, licence and verification time. Verified on 2026-10-28.

**Privacy.** De-identified x-ray coronary angiograms published for research. They stay in the
git-ignored `data/` folder; no image, mask or derived per-image output is ever committed.
Reports contain only aggregate metrics and a few figures generated from public dataset images.

**Structure (as extracted, inspected 2026-10-28).**

```
data/raw/arcade/arcade/
  syntax/{train,val,test}/images/<id>.png        1000 / 200 / 300 images
  syntax/{train,val,test}/annotations/<split>.json   COCO
  stenosis/{train,val,test}/images/<id>.png      1000 / 200 / 300 images
  stenosis/{train,val,test}/annotations/<split>.json COCO
```

- Images: PNG, 8-bit single-channel greyscale, all 512 × 512.
- COCO keys: `images` (`id`, `file_name`, `width`, `height`, ...), `annotations` (`id`,
  `image_id`, `category_id`, `segmentation` = one polygon per annotation, `bbox`, `area`,
  `iscrowd`, `attributes.occluded`), `categories`. `info` / `licenses` are empty
  placeholders.
- Categories (identical list in both tasks): ids 1–25 are SYNTAX-score coronary segments named
  `1`–`16`, `9a`, `10a`, `12a`, `12b`, `14a`, `14b`, `16a`, `16b`, `16c` (id → name: 1–9 → `1`–`9`,
  10 → `9a`, 11 → `10`, 12 → `10a`, 13 → `11`, 14 → `12`, 15 → `12a`, 16 → `13`, 17 → `14`,
  18 → `14a`, 19 → `15`, 20 → `16`, 21 → `16a`, 22 → `16b`, 23 → `16c`, 24 → `12b`, 25 → `14b`);
  id 26 is `stenosis`.
- `syntax` task: segment polygons only (categories 1–25; 4,976 / 1,168 / 1,672 annotations in
  train / val / test, median 5–6 per image; every image has at least one).
- `stenosis` task: only category 26 (1,625 / 406 / 386 annotations; 3 train images have none).

**Checks (pixel-level MD5 of the decoded images).**
- `syntax` train / val / test share no images (no leakage between our splits).
- `syntax/train` holds 5 duplicated images (995 unique of 1,000); left as provided.
- The two tasks use different images, except that 123 `stenosis/test` images are
  pixel-identical to `syntax/test` images. So `stenosis` images have no vessel polygons.

**How vstent uses it.** Vessel masks = union of all `syntax` segment polygons of an image
(rasterised with pycocotools). Segmentation is trained on `syntax/train`, tuned on
`syntax/val` and reported on `syntax/val` and `syntax/test`. The `stenosis` task is used only
for evaluation overlays (its boxes on `stenosis/val` images).
